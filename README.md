# hydrogeochem

Краткая инструкция по сборке контейнерного образа, упаковке его в архив и переносу на удаленный сервер. Приложение обслуживается shiny-server и публикуется по адресу `http://СЕРВЕР:8180/`.

## Требования

Для сборки требуется установленный Docker с правами на обращение к демону, а также доступ в сеть для загрузки базового образа и пакетов R. Для работы самого приложения необходим исходящий доступ к `www.googleapis.com` и `accounts.google.com`, поскольку чтение таблиц выполняется при каждом открытии сеанса.

## Сборка образа

Сборка выполняется из корня репозитория

```bash
sudo docker build --network=host -t hydrogeochem:latest .
```

Ключ `--network=host` является обязательным. Без него шаг установки пакетов завершается ошибкой, поскольку контейнер сборки не может обратиться к индексу `https://p3m.dev/cran/__linux__/noble/latest/src/contrib/PACKAGES`. Это связано с тем, что контейнер использует собственную подсистему разрешения имен и не наследует маршруты хоста через интерфейс `amn0`. Указанный ключ помещает сборку в сетевое пространство имен хоста, после чего индекс пакетов разрешается за несколько секунд.

В образе используется базовый rocker/shiny-verse с R 4.6.1, который уже содержит tidyverse и набор системных библиотек. Дополнительно устанавливаются `libsodium-dev` и `libssl-dev`, необходимые пакетам shinyauthr и googlesheets4 соответственно. Порт shiny-server изменен с 3838 на 8180, а рабочий каталог приложения размещен в `/srv/shiny-server/hydrogeochem`. Директива `site_dir` заменена на `app_dir`, поэтому приложение занимает корневой адрес сервера.

## Проверка образа

Перед упаковкой имеет смысл убедиться, что учетные данные и файлы данных попали в образ, а слушаемый порт задан верно

```bash
sudo docker run --rm hydrogeochem:latest \
  ls -la /srv/shiny-server/hydrogeochem/ /srv/shiny-server/hydrogeochem/.secrets/

sudo docker run --rm hydrogeochem:latest \
  grep listen /etc/shiny-server/shiny-server.conf
```

## Упаковка в архив

Собранный образ упаковывается в сжатый архив для последующей передачи

```bash
sudo docker save hydrogeochem:latest | gzip > hydrogeochem-$(date +%Y%m%d).tar.gz
ls -lh hydrogeochem-*.tar.gz
```

Имя архива содержит дату сборки. Такие файлы исключены из индекса git соответствующей строкой в `.gitignore`.

## Перенос на сервер

Передача выполняется по SSH одним потоком, поэтому промежуточный файл на диске не создается

```bash
sudo docker save hydrogeochem:latest \
  | gzip \
  | ssh USER@SERVER 'gunzip | sudo docker load'
```

Значения `USER` и `SERVER` заменяются на имя пользователя и адрес целевой машины. На сервере должен быть установлен Docker, а порт 8180 должен быть открыт брандмауэром.

## Запуск

```bash
ssh USER@SERVER 'sudo docker run -d \
  --name hydrogeochem \
  -p 8180:8180 \
  --restart unless-stopped \
  hydrogeochem:latest'
```

Политика `unless-stopped` обеспечивает автозапуск контейнера после перезагрузки машины.

## Проверка работоспособности

```bash
curl -sI http://SERVER:8180/
ssh USER@SERVER 'sudo docker logs hydrogeochem'
```

Обращение к адресу запускает R-процесс, который выполняет аутентификацию googlesheets4 по сохраненному токену и обращается к таблицам. Отсутствие сообщений об ошибке аутентификации в журнале означает, что токен работает в безбровузерном режиме. Тексты ошибок приложения также выводятся в журнал, поскольку rocker перенаправляет содержимое `/var/log/shiny-server` в поток STDOUT.

## Обновление

Обновление выполняется пересборкой и повторной передачей образа с последующей заменой контейнера

```bash
sudo docker build --network=host -t hydrogeochem:latest .
sudo docker save hydrogeochem:latest | gzip | ssh USER@SERVER 'gunzip | sudo docker load'
ssh USER@SERVER 'sudo docker rm -f hydrogeochem && sudo docker run -d --name hydrogeochem -p 8180:8180 --restart unless-stopped hydrogeochem:latest'
```

## Ограничения

- Образ содержит файл `.secrets` с токеном доступа к Google и файл `user_base.csv` с учетными данными пользователей в открытом виде, поэтому его публикация в общедоступном реестре не допускается. Перенос выполняется исключительно по SSH.
- Файл `chem_data.rds`, который перезаписывается кнопкой обновления данных, хранится внутри контейнера. При удалении и повторном запуске контейнера эти записи теряются и заменяются копией, вошедшей в образ.
- Данные мониторинга в файле `google_data.rds` приложением не перезаписываются, поэтому они остаются неизменными на момент сборки образа.
- Конфигурация shiny-server закрепляет за приложением корневой адрес, поэтому на этом же порту второе приложение не публикуется. Для него потребуется отдельный порт либо дополнительный блок `location`.
